# 2026-11-18

## ElderMonitor 项目立项（设计阶段）

- 用户需求：「老头监控器」——多直播同屏网格监看，每路独立音量/静音（主听调大、唱歌调小、只看画面静音）
- 关键决策（均已与用户确认，见 PROJECT.md §6）：
  - Rust + winit + libmpv，放弃 Web/Electron（内存减半、延迟可控；解码都是硬解）
  - 渲染路线**调整为 A 优先**（2026-11-18 二次确认）：用户将 macOS/Windows 双机并行开发，B 方案（wid）在 mac 完全不可用会让 mac 侧长期无法调试渲染 → 改为 render API 主线（M1 单路直渲验证 interop 闸门，M2 多路 FBO 纹理合成），B 仅作 Windows 应急回退；所有里程碑双平台同步交付
  - **macOS 支持已内建**（方案 A 优先后每个里程碑 mac 都能调试）：wid 子窗口在 macOS 不可行；先例 IINA
  - v1 只做 B 站（自实现 getRoomPlayInfo + wbi 签名，移植 TideCap/streamget 已验证实现，不重新踩坑）；flv 直链必须带 Referer 头
  - 分发 = zip 便携（exe + libmpv-2.dll + config/）；不依赖 TideWatch；用户明确解除 .NET 4.6.2 零依赖约定
- 产出文档：PROJECT.md v0.1（权威规范，含里程碑 M0~M5、风险表）、SETUP.md（Win/macOS 双平台开发环境）、README.md（用户线占位）
- 用户将在**别的机器**上开发，文档需自包含
- 下一步：用户在新机器上按 SETUP.md 搭环境，从 M0（workspace 骨架 + libmpv 链接）开始
- 布局模型于 11-19 重构，见 2026-11-19.md
